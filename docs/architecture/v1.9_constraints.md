# Apollo-veo v1.9 架构约束（Non-Interference Contract）

目的：确保 v1.9 扩展不破坏 v1.85 稳态基座。任何违反本约束的改动，视为阻断合并（Block）。

---

## 1) 绝对不允许破坏的稳定面（Must Not Break）

### 1.1 路由契约（API Compatibility）
以下既有路由语义不可变（可加字段、不可改含义）：
- POST /api/tasks/local_upload  （v1.85 自动推进基座）
- POST /api/tasks/{task_id}/subtitles
- POST /api/tasks/{task_id}/dub
- POST /api/tasks/{task_id}/pack
- GET  /api/tasks, /api/tasks/{task_id}
- 以及 v1 路由（如仍被 UI 或外部调用）

约束：
- 参数只允许“新增可选项”；任何必填变更必须走新路由或版本前缀。
- 返回字段可新增；旧字段不可删除/改名/改类型。

---

### 1.2 状态机语义（State Machine）
v1.85 step 名称与推进顺序语义不可破坏：
- local_upload/parse → subtitles → dub → pack
- 自动推进日志口径：AUTO_START / AUTO_PIPELINE_STEP / AUTO_PIPELINE_DONE

约束：
- v1.9 的编排（TaskPlan）必须是“旁路层”：可以影响“建议/计划/可选步骤”，但不得改变 v1.85 的默认推进。

---

### 1.3 存储 Key 与目录口径（Artifact Contract）
以下口径不可随意改动（否则会造成下载/复跑/兼容问题）：
- default/default/{task_id}/...（示例 key 前缀保持稳定）
- video_workspace/tasks/{task_id}/...（本地落盘结构保持稳定）

约束：
- v1.9 新增产物必须走“新增 key / 新增目录”，不得覆盖 v1.85 既有产物命名（除非明确幂等覆盖策略并写入文档）。

---

### 1.4 Smart Pack v1.0 协议不可破坏
- 目录结构、README/manifest 的基本要求不回退
- 既有字段语义不改

约束：
- v1.9 只能“增量增加文件/清单”，不得让 v1.85 校验器失效。
- manifest 校验器：可扩展字段，但不得改变既有字段校验含义。

---

## 2) 扩展方式约束（How to Extend Safely）

### 2.1 新能力优先用“新增对象 + 新路由”
- Scene Pack / Asset Library / TaskPlan：优先新增 route 与新增 data model
- 若必须触及旧路由，仅允许“新增可选字段”，且默认行为保持 v1.85

### 2.2 Schema 演进必须 semver 化
- Scenario Spec / Scene MSC / Smart Pack / ToolCard / TaskPlan / Asset：
  - 必须写版本号字段（*_version）
  - 变更记录进入 release notes

### 2.3 代码组织约束（避免继续变混合架构）
- v1.9 新模块不得把逻辑继续堆进 routers/tasks.py（除“薄路由”外）
- 新增：
  - services/*（业务服务）
  - models/*（pydantic/schema）
  - repositories/*（存储与索引）
  - steps/*（流水线步骤）
- routers 只做：参数校验、调用 service、返回响应

---

## 3) 观测与排障约束（Must Have Observability）

### 3.1 日志字段口径不漂移
- task / step / phase / provider / elapsed_ms 必须持续打印
- 关键动作必须有标志日志（upload done / step done / pipeline done）

### 3.2 幂等与重跑保证
- subtitles/dub/pack rerun 必须幂等
- 任何新增的 v1.9 资产入库与引用也必须幂等（同 asset_hash 不重复入库）

---

## 4) UI 非干扰约束（Front-end Stability)
- v1.85 的 Task Board / Task Workbench / Task New 页行为不可回退
- v1.9 新入口应新增页面或新增区块，不得重写既有交互主路径
- 关键：local_upload 自动推进在 UI 侧不依赖“手点触发”

---

## 5) 合并门槛（Merge Gate）
任何 v1.9 PR 必须提供：
- 回归证据：至少 1 条 local_upload 自动推进到 pack done（日志含 AUTO_PIPELINE_DONE）
- Smart Pack 校验不失败（v1.85 校验器通过）
- 向后兼容说明（列出新增字段/新增路由）
- 风险点与回滚点（如何关掉 v1.9 新功能，回到 v1.85 稳态）
